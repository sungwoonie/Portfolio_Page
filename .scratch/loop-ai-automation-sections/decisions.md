## CLOUDIE 패널을 직접 못 열어 감시 캡처로 전환

- 라운드: 1
- 고른 것: 합성 클릭으로 패널을 여는 걸 3회 시도해 실패한 뒤, 창 ID 를 1.2초마다 캡처해
  내용 영역이 25% 이상 달라질 때만 저장하는 감시 스크립트로 바꿨다. 사용자가 직접 조작하고
  스크립트가 21장을 잡았다
- 왜: 합성 클릭은 방사형 메뉴를 열긴 했지만 캡처 시점에 이미 접혀 있었다. 감시는 사람의 조작
  속도와 무관하게 상태 변화를 잡는다. screencapture 는 -C 없이는 커서를 안 찍고,
  창 ID 캡처는 다른 Space 에 있는 창도 그대로 잡는다
- 안 고친 것: 사용자에게 파일로 캡처해 달라 하기 (왕복이 늘어남), nohup 백그라운드
  (권한이 끊겨 캡처가 전부 실패했다 - 세션 자식 프로세스로 띄워야 했다)

## CLOUDIE 는 한 장이 아니라 8장을 쓴다

- 라운드: 1
- 고른 것: 21장을 축소 이미지 차이로 묶어 12개 화면으로 줄이고, 그중 8장을 캐러셀에 넣었다.
  펼침 방향 5종(중앙 원형, 우하단, 우상단, 좌상단, 좌하단) + 기능 패널 3종
- 왜: 이 앱의 핵심은 "가장자리에 맞춰 부채꼴을 접는다"인데 한 장으로는 그게 안 보인다.
  방향이 다른 5장을 나란히 놓으면 설명 없이도 규칙이 읽힌다. 구름 위치가 매번 다른 것
  자체가 드래그 이동의 증거다
- 안 고른 것: 대표 1장(기능이 안 보임), 12장 전부(접힌 구름만 있는 중복이 섞임)

## 새 이미지를 기존 캐러셀 규칙에 맞춘다

- 라운드: 1
- 고른 것: CLOUDIE 캡처를 `Resources/AI/CLOUDIE/Preview_N.png` 로 저장하고
  카드에 `data-folder="AI/CLOUDIE" data-previews="8"` 만 달았다
- 왜: script.js 의 buildPreviewCarousel 이 이미 `Resources/{folder}/Preview_{i}.png` 로
  경로를 만든다. 파일 이름만 규칙에 맞추면 JS 를 한 줄도 안 고쳐도 된다
- 안 고른 것: AI 전용 캐러셀 함수 추가 (같은 걸 두 벌 유지하게 됨)

## openModal 의 store-links null 참조를 고쳤다

- 라운드: 1
- 고른 것: `.tags` 와 `.store-links` 를 옵셔널 체이닝으로 바꿨다
- 왜: AI 카드는 비공개 저장소라 스토어 링크가 없다. 기존 코드는 두 요소가 항상 있다고
  가정해 null.innerHTML 에서 터졌고, 세 폭 전부에서 모달이 안 열렸다. 검증기의
  pageerror 훅이 이걸 잡았다
- 안 고친 것: AI 카드에 빈 store-links div 를 넣기 (마크업으로 코드 결함을 가리는 것)

## border-radius: 0 을 셰이프 락 예외로 인정

- 라운드: 1
- 고른 것: 검사기가 `0` 을 통과시키도록 했다
- 왜: 카드 안쪽을 꽉 채우는 스크린샷은 모서리가 없어야 맞다. `0` 은 임의 값이 아니라
  "모서리 없음"이고, 셰이프 락이 막으려던 건 4px, 24px 같은 근거 없는 값이다
- 안 고른 것: --radius-none 토큰 추가 (토큰만 늘고 뜻은 같다)
