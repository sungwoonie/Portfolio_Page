# /full-loop — 목표까지 안 끊고 간다

goal 하나를 받아 **사람에게 묻지 않고** 끝까지 간다. 중간에 나오는 결정은 스스로 정하고, 정한 이유를 기록으로 남긴다.

**순차 루프다.** 병렬도 워크트리도 PR도 쓰지 않는다. 브랜치 하나에서 작업 단위마다 검증하고 커밋한다. 병렬이 필요하면 사용자가 내장 `/batch` 를 직접 치는 게 맞다 — 내장 커맨드는 스킬이 아니라서 `Skill` 툴로 부를 수 없다.

## 0. 시작 가드

**2~5번은 하나라도 걸리면 그 자리에서 멈추고 이유를 말한다 — 우회하지 마라.** 1번만은 확인이지 관문이 아니다.

1. **권한 모드 — 멈추지 마라.** 이 루프는 `auto` 또는 `bypassPermissions` 에서 매끄럽게 돈다. 모델은 현재 모드를 직접 읽을 수 없다(공식 문서: *"The mode is set through these controls, not by asking Claude in chat."*) — 그러니 `.claude/settings*.json` 의 `defaultMode` 를 훑어보는 것까지만 하고 **그냥 시작한다.** 사용자에게 확인을 요청하고 답을 기다리지 마라. auto 가 아니면 권한 프롬프트가 뜨는 것 자체가 사용자에게 가는 신호다 — 시작 보고에 "auto 모드가 아니면 프롬프트로 끊깁니다" 한 줄만 남긴다.

2. **깨끗한 워킹트리.** `git status --porcelain` 이 비어야 한다. 안 비었으면 멈춘다 — 사용자의 미커밋 작업을 루프 브랜치로 끌고 들어가면 이후 모든 커밋이 그걸 물고 간다.

3. **진행 중인 루프.** `git branch --list 'loop/*'` 로 확인한다. 있으면 **새로 시작하지 않는다** — 한 번에 goal 하나다. 그 브랜치를 알리고 이어갈지(→ 5절) 버릴지 묻고 멈춘다.

4. **goal.** `$ARGUMENTS` 가 비었으면 **"목표가 뭡니까?" 한 줄만 묻고 멈춘다.** 목표 없는 자율 루프는 사고다. goal 에서 짧은 영문 kebab-case 슬러그를 만든다(`<goal-slug>`).

5. **검증 명령.** 이 프로젝트를 어떻게 검증하는지 **지금** 찾는다 — README, `package.json`, `Makefile`, `ci/`, 유니티면 배치모드 컴파일. **못 찾으면 시작하지 않고** 어떤 명령을 쓰면 되는지 사용자에게 묻는다. 검증 없이 도는 루프는 틀린 코드를 아주 부지런히 쌓는다. 이 탐색을 라운드 중간으로 미루면, 이미 여러 커밋을 쌓은 뒤에야 검증할 수 없다는 걸 알게 된다.

## 1. 브랜치와 기록

```
git switch -c loop/<goal-slug>
```

**`main` 은 이 스킬이 절대 안 건드린다.** 커밋 직전마다 `git branch --show-current` 가 `loop/` 로 시작하는지 확인한다 — 아니면 커밋하지 말고 멈춘다. 재개 경로에서 브랜치를 잘못 잡는 사고를 여기서 막는다.

`.scratch/loop-<goal-slug>/decisions.md` 를 만들고 goal 과 **완료 조건**을 적는다. 완료 조건은 증거로 확인 가능한 형태여야 한다 — "잘 동작한다"가 아니라 "`<검증 명령>` 이 0으로 끝난다".

## 2. 루프

한 라운드 = **작업 단위 하나**. 목표에 닿거나 중단 조건에 걸릴 때까지 반복한다.

### 2-1. 다음 단위를 고른다

**한 커밋으로 끝낼 수 있는 크기**로 자른다. 그리고 이 단위가 **완료 조건 중 어느 것을 겨냥하는지** 명시한다. 어느 조건에도 안 걸리는 단위는 만들지 마라 — 그게 루프가 목표와 무관한 일을 부지런히 하다 영원히 안 끝나는 경로다.

### 2-2. 구현하고 검증한다

구현한 뒤 0단계에서 확보한 검증 명령을 돌린다. **출력을 실제로 읽는다.**

- **통과** → 커밋. 메시지 첫 줄에 무엇을 했는지, 본문에 어느 완료 조건을 겨냥했는지.
- **실패** → 고치고 다시 돌린다. **같은 단위에서 3회까지.** 3회로 안 되면 커밋하지 말고 그 단위를 접는다. 무엇을 시도했고 왜 실패했는지 `decisions.md` 에 적고 다음 단위로 넘어간다. 같은 벽을 무한히 치지 않는다.

### 2-3. 목표에 닿았는지 판정한다

**증거로 판정한다.** "다 한 것 같다"는 판정이 아니다. 완료 조건을 하나씩, 실제 명령 출력과 실제 파일 내용으로 대조한다.

- **미달** → 2-1 로.
- **충족으로 보임** → 아직 끝난 게 아니다. 2-4 로.

### 2-4. 코드리뷰 — 종료 직전 한 번

완료 조건이 다 충족돼 보이면, **끝내기 전에** [`fcode-review`](../fcode-review/SKILL.md) 스킬을 부른다. `Skill` 툴로 호출하면 된다 — 그 스킬은 `disable-model-invocation` 이 없어서 부를 수 있다.

루프 안에서는 **사용자에게 묻지 않는다.** 기본 관점 전부로 돌린다.

- **안 고친 심각한 지적이 없음** → 6절. 진짜 끝.
- **남아 있음** → **미달로 친다.** 그 지적들을 다음 라운드 작업 단위로 만들고 2-1 로 돌아간다.

리뷰를 라운드마다가 아니라 여기서 한 번만 도는 이유는, 단위마다 3~4개 에이전트를 띄우면 구독 한도가 버티지 못해서다. 단위별 검증은 2-2 의 검증 명령이 이미 하고 있다.

## 3. 중단

**진전 없는 라운드가 2회 연속이면 멈추고 보고한다.** 진전 = 이번 라운드에 커밋이 생김. 커밋 0인 라운드가 두 번 이어지면 루프는 수렴하지 않는 것이고, 더 도는 건 토큰만 태운다.

멈출 때는 **왜 막혔는지** 보고한다: 마지막 두 라운드가 뭘 시도했고, 어디서 실패했고, 사람이 뭘 정해줘야 뚫리는지.

## 4. 중간에 나온 결정

goal 을 잡을 때 안 나온 갈래가 반드시 나온다. **멈추지 말고 정한다.** 그리고 `.scratch/loop-<goal-slug>/decisions.md` 에 append 한다:

```markdown
## <결정 한 줄>

- 라운드: <N>
- 고른 것: <무엇을>
- 왜: <근거 — 코드베이스의 기존 패턴, 완료 조건과의 정합, 되돌리기 비용>
- 안 고른 것: <대안과 탈락 사유>
```

**정한 것보다 왜 정했는지가 중요하다.** 기록 없는 자율은 사후 검토가 불가능하다.

단, 아래는 정하지 말고 **멈춰서 보고한다** — 되돌리기 비용이 루프 하나를 버리는 것보다 큰 것들:

- `main` 이나 다른 사람 브랜치를 건드려야 풀리는 일
- 외부에 돌이킬 수 없는 영향 (배포, 심사 제출, 프로덕션 데이터, 결제)
- 새 유료 의존성·외부 서비스 계약

## 5. 재개

세션이 끊겼다 다시 `/full-loop` 을 치면, **별도 상태 파일 없이 git 만 보고 복원한다:**

- `git log loop/<goal-slug>` = 지금까지 끝낸 단위
- `.scratch/loop-<goal-slug>/decisions.md` = 지금까지 정한 것과 접은 단위
- 남은 완료 조건 = 아직 할 일

복원한 상태를 한 줄로 보고하고 2절부터 이어간다. **0단계 가드는 재개에서도 전부 다시 돈다** — 특히 권한 모드와 워킹트리. 상태 파일을 따로 쓰지 않는 이유는, 갑자기 죽으면 그 파일이 제일 먼저 낡기 때문이다.

## 6. 끝

- 커밋 수와 각 커밋이 겨냥한 완료 조건
- 검증 명령과 그 **실제 출력**
- 접은 단위와 그 이유
- `decisions.md` 에 쌓인 결정 목록
- 다음 한 줄: `git switch main && git merge loop/<goal-slug>` — **실행하지는 마라.**

병합이 끝나면 사용자가 `git branch -d loop/<goal-slug>` 로 지운다고 알린다. **안 지우면 다음 `/full-loop` 이 0단계 3번에서 그걸 "진행 중인 루프"로 오판한다.**

## 범위 밖

- **`main` 병합** — 사람이 한다
- **한 번에 goal 둘 이상** — 진행 중이면 거부한다
- **롤백 명령** — `git branch -D loop/<slug>` 한 줄이면 된다. 그래서 push 도 안 한다(리모트에 올린 건 로컬 삭제로 안 사라진다)
- **스케줄/cron** — 내장 `/loop`·`/schedule` 과 안 엮는다. 사용자가 칠 때 한 번 돈다
- **병렬·워크트리·PR** — 내장 `/batch` 것이고, 스킬 본문은 그걸 호출할 수 없다
