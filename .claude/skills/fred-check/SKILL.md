# /fred-check — 결과물을 반박으로 친다

작업이 "끝났다"는 주장을 받아 **반박을 시도한다.** 반박이 전부 실패하면 그때가 진짜 끝난 것이고, 하나라도 성립하면 목표 미달이 증거와 함께 드러난다. 검증하는 건 **결과물**(코드·문서·설정)이다 — 계획이 말이 되는지는 `grilling` 이 이미 캐물었다.

## 먼저 — 넘길 것

| 요청 | 넘길 곳 |
|---|---|
| 계획·명세가 말이 되는지 | `grilling` (계획 체인) |
| 코드 품질 (버그·성능·단순화) | `/fcode-review` |
| 보안 점검 | `/security-review` |
| 빌드·테스트만 돌리기 | 검증 명령 직접 실행 |

겹치게 만들지 마라. 이 스킬이 보태는 건 **목표 부합성** 하나다: 하겠다던 것이 실제로 됐는가, 빠진 요구는 없는가.

## 1. 기준을 잠근다

반박하려면 반박할 주장이 필요하다. 우선순위:

1. **인자** — `/fred-check <목표·완료 조건>` 으로 받은 것
2. **대화 맥락** — 인자가 없으면 직전 작업의 목표·완료 조건을 추출한다. `/full-loop` 직후면 `.scratch/loop-*/decisions.md` 의 완료 조건이, fask-loop 인터뷰 직후면 잠근 결정이 그대로 기준이다

추출한 기준은 **시작 전에 사용자에게 한 번 확인받는다** — "이 기준으로 검증합니다." **기준이 확정되기 전에는 반박 에이전트를 쏘지 않는다.** 틀린 기준으로 하는 검증은 전부가 헛돈다. 인자로 받았으면 확인 없이 그대로 쓴다.

각 조건은 **증거로 판정 가능한 주장**으로 정규화한다: "잘 동작한다" → "`<명령>` 이 0으로 끝난다", "문서화했다" → "README 에 해당 절이 있다".

## 2. 반박한다

`Agent` 툴로 **한 메시지에 모아** 병렬로 쏜다:

- **조건당 반박 에이전트 1개** — 프롬프트는 검증이 아니라 **반박**이다: "다음 주장을 반박하라: \<조건\>. 명령을 실행하고 파일을 읽어 주장이 무너지는 증거를 찾아라. 못 찾으면 못 찾았다고 하라." 조건이 6개를 넘으면 에이전트당 2~3개씩 묶는다 — 에이전트 수가 구독 한도를 잡아먹는다
- **빠진 요구 스위퍼 1개** — 조건 목록에는 없지만 목표가 암시하는 요구가 빠졌는지 훑는다: 빈 상태, 실패 경로, 문서 갱신, 이 레포라면 「스킬 추가와 README 갱신은 같은 커밋」 같은 규약

에이전트에게 주는 것: 목표 전문, 맡은 조건, 결과물 위치(브랜치·diff 범위·파일). **읽기와 실행만 — 파일 수정은 금지라고 명시한다.** 심판이 경기장을 고치기 시작하면 판정이 오염된다.

에이전트가 조건마다 돌려줄 것:

- **반박 성립** — 증거(명령 출력, `파일:줄`)와 함께
- **반박 실패** — 조건이 버텼다는 확인 증거와 함께
- **판정 불가** — 증거를 찾을 수 없는 이유

**증거 없는 반박은 버려라.** "안 됐을 수도 있다"는 반박이 아니라 소음이다.

## 3. 판정서

대화에 보고한다 — **파일로 남기지 않는다.** 단발 검증에 부산물을 만들지 않는다.

- **버틴 조건** — 확인 증거 한 줄씩
- **반박된 조건** — 증거와 함께
- **판정 불가** — 왜
- **스위퍼가 찾은 빠진 요구**

전부 버텼으면 그렇게 보고하고 **끝낸다.** 질문할 게 없다.

## 4. 지적별로 묻고, 다 정해지면 고친다

반박된 지적과 빠진 요구를 **fask 처럼 한 번에 하나씩** `AskUserQuestion` 으로 묻는다 — 고칠까 / 무시할까 / 다르게 갈까, 추천안을 달아서. **여러 개를 한 번에 묶지 마라.**

전부 결정되면 **고치기로 한 것만** 수정한다:

- 수정만 한다 — **커밋하지 않는다.** 커밋은 사용자(또는 진행 중인 루프)의 것이다
- 수정 후 자동 재검증은 없다 — 수정이 미덥지 않으면 사용자가 `/fred-check` 를 다시 친다

## 범위 밖

- **명세서 자체 검증** — 계획이 말이 되는지는 `grilling` 것이다
- **코드 품질** — [`/fcode-review`](../fcode-review/SKILL.md) 것이다. 여기서 버그를 찾기 시작하면 두 스킬이 같은 걸 두 번 본다
- **자동 재검증 루프** — 한 호출에 한 라운드
- **커밋·병합** — 수정까지만 한다
- **자동 발화** — 훅으로 안 뜬다. 사용자가 치거나 체인이 넘길 때만
